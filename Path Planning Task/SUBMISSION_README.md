# Formula Student Driverless: Path Planning

This repository contains an expert-level Path Planning module for a Formula Student Driverless vehicle. The approach is based on geometric track synthesis and shape-preserving parametric splines to safely map the boundaries and output a smooth, drivable trajectory.


### Step 1: Data Separation
**Description:** The algorithm ingests raw sensor data and categorizes the cones by their position relative to the track.
A straightforward logical filter checks the flag associated with each coordinate: $color=1$ designates the left boundary (Blue), and $color=0$ designates the right boundary (Yellow).

### Step 2: Case 1 (No Cones Detected)
**Description:** In the event of a total sensor miss or an empty track segment, the car must continue safely along its current trajectory. 
**Math:** Ray-casting is used based on the car's current pose $(x_{car}, y_{car})$ and yaw angle ($\theta$). Future points are generated iteratively:
$$x_i = x_{car} + i \cdot \text{step} \cdot \cos(\theta)$$
$$y_i = y_{car} + i \cdot \text{step} \cdot \sin(\theta)$$

### Step 3:  Sorting
**Description:** Raw cone arrays are often unordered. To build a coherent track boundary, cones are sorted sequentially into a chain along the track layout.
**Math:** A greedy nearest-neighbor algorithm using Euclidean distance. The first cone $C_1$ is selected by minimizing the distance to the car: $\min \sqrt{(c_x - x_{car})^2 + (c_y - y_{car})^2}$. Each subsequent cone $C_i$ is found by minimizing the distance to the *previous* cone $C_{i-1}$, ensuring the arrays mathematically follow the track's topology.

### Step 4: Case 2 Single Boundary Found (Completely Empty Array)
**Description:** When the camera only detects cones on one side , we mathematically construct "virtual cones" on the missing side to provide a boundary for midpoint generation. Generate a new virtual cone.
**Math:** Estimate the track tangent vector $V = P_{i+1} - P_{i}$ along the known cones. Normalize this vector to $\hat{u} = \frac{V}{||V||}$. Using a $90^\circ$ rotational matrix, we compute the perpendicular normal vector $\hat{n}$ pointing inward toward the track center. The virtual cones are then generated by shifting the known boundary inward by the estimated track width $W$:
$$P_{virtual} = P_{known} \pm W \cdot \hat{n}$$

### Step 5: Generating Midpoints & Handling Case 3: Uneven Arrays
**Description:** The optimal racing line for a standard drive is assumed to be the centerline. We generate this by bisecting the track.
**Math:** For matched indices, the symmetrical midpoint $M_i$ is the average of the two boundaries:
$$M_i = \left( \frac{x_{blue,i} + x_{yellow,i}}{2}, \frac{y_{blue,i} + y_{yellow,i}}{2} \right)$$
If one array has more cones (uneven arrays), the excess cones are shifted inwards along a locally projected normal vector by $\frac{W}{2}$ to continue the centerline accurately.

### Step 6: Initial Path Generation
**Description:** The car's dynamic heading must be smoothly integrated into the midpoints so the vehicle doesn't attempt to snap laterally.
**Math:** The raw waypoint array is initialized with the car's current position $(x_{car}, y_{car})$ and a short-distance projected point strictly enforcing the initial yaw vector:
$$P_{init} = (x_{car} + 0.5\cos(\theta), y_{car} + 0.5\sin(\theta))$$
This point is prepended to the generated midpoints to form the raw skeleton of the path.

### Step 7: Smoothing and Resampling
**Description:** The raw midpoints are jagged polylines. To satisfy kinematic constraints and output step sizes $\le 0.5m$, the skeleton is smoothed and dense-sampled.
**Math:** 
1. **Parameterization:** We calculate the cumulative chord length $s_i = s_{i-1} + ||P_i - P_{i-1}||$ to act as the independent parameter.
2. **Shape-Preserving Splines:** We interpolate $x(s)$ and $y(s)$ using a **PCHIP Interpolator** (Piecewise Cubic Hermite Interpolating Polynomial). Unlike standard cubic splines which suffer from Runge's phenomenon (wild overshoots on sharp turns causing boundary collisions), PCHIP strictly preserves monotonicity.
3. **Linear Extrapolation:** If the required target length exceeds the data, we extract the tangent at the final data point $\frac{dP}{ds}$ and linearly extrapolate the trajectory.
4. **Adaptive Subdivision:** We uniformly sample the spline, then recursively check the Euclidean distance between points. If $\sqrt{(x_k - x_{k-1})^2 + (y_k - y_{k-1})^2} > 0.5m$, we insert parametric midpoints, strictly guaranteeing the density requirement everywhere.
